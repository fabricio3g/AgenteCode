# Agente — Project Context

## Goal

Build a development-engineer tool: a keyboard-first terminal coding agent (Rust) with a clean, minimal TUI, backed by a robust agent core (parallel tools, subagents, compaction, prompt caching) and a path toward editor embedding (ACP / Electron).

## Instructions

- Remove all duplications in UI code
- Implement proper scroll handling
- No harsh borders, no bright colors — use subtle, adaptive colors
- Keep the chat display free of "assistant"/"user" labels — icons only
- Keep the UI clean and minimal
- Keyboard-first design
- Every change compiles with zero warnings; tests stay green
- Never add AI tools or services as commit authors or coauthors; commits use the user's Git identity

## Design decisions

- **Scannable UI** (both surfaces): people hunt for one thing, they never read a whole screen, so every layout serves scanning. Lock content to edges — labels hard left, values/actions hard right, each row an edge for the next; centre only what is not meant to be read (an empty-state illustration). Fix density by differentiating (group, add icons/avatars/chips), not by adding whitespace. Show, don't tell: a recognisable glyph or chip beats another label or tooltip. Emphasis is contrast with neighbours: defaults and off states stay grey and uncoloured so the one changed value finds the eye. Hue that identifies a kind is differentiation, not emphasis — the per-kind tiles in Settings → Artifact types and the Design starters keep their colours. Prefer a column edge to another card — no borders on borders, no stacked radii. In the TUI: `modal_card` is borderless (a status tint is one `●` before the title), modal footers and approval buttons start on the content's left edge, healthy/pass/default states are dim, and the unfiltered command palette is grouped into Session / Model / Tabs / View / System
- **Composer pill** (desktop, Home/Code/Design share it): the field and its bar are one 28px-radius sheet — `--composer-radius: 1.75rem`, a 1px 8% ring, one whisper of shadow, and an 18px inset. The prompt takes `--text-prose` so Settings → Text size moves it with everything else; the placeholder is a hint (`--composer-placeholder`), not a disabled value. The bar is one line of 32px controls with round hover bands and no dividers; the 34px round send is the only filled control, flat 12% when idle and lifted 4% on hover. Starter links carry no tooltip: hovering (or focusing) one writes its prompt into the empty field's placeholder, where the words will land
- **Owned spans**: `Span<'static>` with helper `s(text, style)` to avoid lifetime issues
- **No borders on popups**: dialogs are floating panels on `BG_PANEL`; centered settings dialogs share `widgets::{modal_card, modal_footer}`
- **Dark/light theme**: `/theme` toggles; all widgets route colors through `style.rs` accessors; the syntect theme follows the app theme. Both TUI palettes are the desktop's tokens, so the two surfaces read as one product: graphite canvas `#1c1c1c`, panels `#232323`, fills a step lighter, neutral text (`#b3b3b3` muted), one orange accent `#e8793a` for focus and selection (no teal/blue/purple second hues), the desktop's status colours, headings and bold at full foreground, list markers and code-fence labels muted, and settled `◆ Run` markers and durations grey (`META`)
- **Custom markdown parser**: headings, bold, italic, code, lists, rules, tables, task lists, strikethrough
- **One list look**: every picker renders through `widgets::pick::pick_list` (`›` accent marker + `BG_ACTIVE` band + bold label, `◈` for the item in effect, dim group headers) and filters through `pick::search_field`; key hints always use `footer_hints` grammar (`Ctrl+X action · Esc close`)
- **Running tools**: a live row shows its elapsed time and, when silent, why (`| tail` pipes print at the end); click it for the live output view (`widgets/process_view`, follows the tail, `s` stops, survives completion). The live buffer keeps the newest 32 KB. `task` spawn results are hidden behind their subagent card
- **Session tabs** (`state/tabs.rs`, `app/tabs.rs`, `widgets/tabs.rs`): several sessions open at once, each with its own agent, config (model), todos, plan, subagents, draft and scroll. The active tab lives in `AppState` so every widget is unchanged; background tabs are `TabState`s swapped in only to apply their own agent events (routed by the task ids each tab issued via `next_task_id`), so their turns keep running. The strip appears at the top once two tabs exist: number, status mark (accent `●` working, warning `◆` needs approval, success `●` finished while away), `×` on the active/hovered tab, `+`; overflow slides to keep the active tab visible. F2 / `/tab` opens one, Ctrl+PgUp/PgDn switch, `/close-tab` or `×` closes (never the last, never a working one). Quitting saves every tab and prints each resume id
- **Clipboard**: one `arboard::Clipboard` for the whole process (`clipboard.rs`) — a per-copy instance dropped at once made arboard print a warning onto the TUI (and lost the copy on Linux)
- **Message queue**: Enter while a turn runs queues the message (preview rows above the composer, no chat bubble yet); Enter again on the empty composer sends the queue *now* — it goes into the turn's `UserInbox`, the loop takes it at the next step boundary (after a tool round, or instead of finishing) and emits `UserMessagesInjected`, which turns it into bubbles in the order the model saw them. Up on an empty composer pulls the last unsent message back to edit. Whatever the turn never took runs as the next turn
- **Media input** (`core/media.rs`, `tui/media_consent.rs`, `app/media.rs`): images, audio, video and PDFs ride on `Message.attachments` / `ChatEntry.attachments` as references to a content-addressed copy in `~/.agente/attachments/` (sessions never store bytes) validated by magic-byte signatures and pre-decode size caps (inline `data:` URLs only; remote URLs and SVGs are rejected); providers base64 them at request time — OpenAI chat `image_url`/`input_audio`/`video_url`/`file`, Anthropic `image`/`document`, Gemini `inlineData`, Responses `input_image`/`input_file`. Model support comes from models.dev `modalities.input` / OpenRouter `architecture.input_modalities` (`capabilities.input_modalities`); the composer refuses a send the model can't take, and history sent to another model turns unsupported media into a text note. Attach by dropping/pasting a path (quoted, `\ `-escaped or `file://`), Ctrl+V with an image on the clipboard, or `@` on a media file; chips show above the text (Backspace on an empty composer removes the last), bubbles list them. Each kind (`image`, `audio`, `video`, `pdf`) has a 3-state policy — `ask` (Enter once, `a` always, Esc no), `allow` (`allow_media`), or `block` (`deny_media`, strictly enforced in TUI, Desktop, and every daemon RPC: `media.import`, `turn.start`, `turn.steer`, `llm.stream`, `llm.complete`). Compaction drops old attachments with a note; estimates count them
- **Paste chips**: any paste of 2+ lines or 20+ characters collapses into an accent chip in the composer — `[#1 +12 lines]`, or `[#2 +58 chars]` for one line — deleted whole by Backspace and expanded on submit; shorter pastes stay inline and editable. Chip numbers never repeat within a draft; history keeps the expanded text. A pasted path to media attaches the file instead
- **Plans**: each `present_plan` writes its own file `<project>/.agente/plans/<date>-<title-slug>.md` (a revision with the same title updates it), so plans from other sessions and tabs are never overwritten
- **Resume**: quitting prints `Resume with: agente --resume <session-id>`; `agente --resume <id|prefix>` reopens it, bare `--resume` opens the picker
- **Sent messages**: your prompts render as a padded card with a full-height accent rail; hover lifts it and shows `revert · fork · copy`; click opens `message_actions` — Revert undoes the file edits made after it (undo stack, so Redo works) and rewinds chat + context, Fork opens a new session up to it; both put the prompt back in the composer
- **Hit map + hover**: widgets register interactive rects in `state.ui.hits` while painting; hovering a list row selects it, clicking selects + sends Enter; buttons lift to `BG_HOVER`; chat cards get a post-paint `hover_tint` (hover never enters render cache keys); pointer moves repaint only when `pointer_fingerprint` changes
- **One scrollbar**: chat, plan review and subagent detail all paint `widgets::scrollbar` (thin thumb, brighter on hover/drag, `HitTarget::Scrollbar` carrying its geometry — press jumps, drag scrubs, over modals too) and show a `12–25 of 120` position
- **Eased scrolling**: wheel / Ctrl+↑↓ / PageUp/Down go through `glide_by` (45% of the remaining distance per frame); `reduce_motion` in config snaps instead
- **Subtle motion**: `state::anim::Tween` (cubic ease-out) drives every transition — a sent prompt glides the transcript up (`glide_to_bottom`) while only its block fades in; floating dialogs ease in over the backdrop; the chat hover band eases in. Never re-fade text that was already on screen (streamed replies). `reduce_motion` starts no tweens; the visual harness runs with it on
- **Desktop motion ladder** (`app.css` `--motion-*`): five steps — `instant` 90ms, `fast` 150ms, `normal` 200ms, `smooth` 280ms, `dialog` 300ms — and three curves: `--motion-ease` standard, `--motion-ease-out` for anything entering, `--motion-ease-in` (Carbon's exit curve) for anything leaving. The numbers are the average of what Carbon (70/110/150/240/400/700), Fluent (83/167/250) and Material (~100/200/300) publish, rounded. Rules that travel with them: repeat feedback (hover bands, chip colours on rows crossed dozens of times a day) runs at `instant` or not at all; never animate from `scale(0)` (start at 0.9+); nothing exceeds 300ms; a popover scales from its trigger (`transform-origin`); `html.a11y-reduce-motion *` zeroes every duration and keyframe. Live timings: `design-plans/motion/index.html`
- **Hero**: the welcome card carries the app mark in shaded ASCII art (`welcome::ICON`: a 26×10 tilted Quasar Orbital `-28°` using `.,:;+=*#@`, each glyph blended from the card to the foreground so it stays crisp monochrome on dark and light themes with no tile behind it; shown when the canvas has ten spare rows) and floats on the landing page's tile field (`welcome::TileField`: horizon glow, corner light, swell, rings and embers, dithered into six levels and painted as separated half-block squares, one per two columns; ~15 fps via `wants_ambient_paint`, frozen under `reduce_motion` and in tests); New session dismisses the hero and hands keys to the composer
- **Brand**: "Agente Code" — a tilted Quasar Orbital (`-28°`) rendered as a 15×15 shaded Matrix Field of rounded-square tiles (`rx = 0.22 * size`) with four corner stars on a black rounded tile inside a graphite rim. `examples/gen_brand.rs` generates the whole set with no font: full/large sizes (`≥ 48 px`) sit inside the graphite-rimmed tile, while optical small sizes (`≤ 32 px`) scale the same 15×15 shaded Matrix Field onto a full-bleed dark tile (`#0d0d0e`) so the rim never smears. Outputs: tile SVG and small optical SVG, PNGs 16–1024 (Desktop ships `apps/desktop/renderer/public/app-icon.png` at 512 px and `apps/desktop/build/app-icon-dev.ico`), `favicon.ico`, and dark/light lockups whose wordmark comes outlined from `agente-code-wordmark.svg` (Space Grotesk Medium, OFL). `brand.rs` embeds the small SVG as the gallery/inspector favicon; `site/assets/` carries copies and the site nav draws the same 15×15 shaded Matrix Field in the text colour; the Linux launcher (`packaging/linux/`) installs the PNG ladder and SVG
- **Manual word-wrapping** via `wrap_line()` (never `Wrap` on `Paragraph`) to avoid scroll bugs
- **Syntax highlighting**: `syntect` via `syntax_highlight.rs` for code blocks
- **Transcript grammar**: uniform `◆ Run <verb> <subject>` tool rows, `◇` collapsed thoughts with a one-line preview, `∴` activity line, `Worked for Ns` turn footer, `┃` error rails, rounded composer with the model on the bottom border; a status row under it carries `mode │ $spend · cache% │ context meter` — the one place the mode shows (the header only shows cwd + git)
- **Live tile meter** (`CodeLiveStatus.svelte` → `TileMeter.svelte`, keyframes in `app.css`): the run's status line carries the landing page's mosaic at indicator scale — two columns of tiles a drop steps through, one keyframe for all eight tiles, no canvas and no rAF. `busy` runs a drop every 0.31s a cell while events are arriving and falls back to a 1.25s drizzle after 1.2s of silence, so a stalled tool looks stalled; an approval stops the rain mid-fall and turns the square amber, the columns blinking in alternation. The alpha ramp is compressed against the hero's (`alpha = i^1.35` disappears at four pixels on white), and the base styles *are* the reduced-motion still, so motion off shows a designed frame instead of a frozen animation
- **Say it once** (desktop live activity): each fact about a run has one place. The running step row names the call, so the live line under it says only `Working · 12s` (plus a subagent wait, or what has no row yet: thinking, writing, preparing a call); an approval is answered in one place, `ApprovalBar` (`features/shared/composer/`) on the composer sheet — Code's and the chat composer's (Home, Design, Roleplay) — ("Allow this edit?" by kind, "Allow this action?" over a connected service's action, the target — a click scrolls to its diff — with +/− counts, Deny `Esc` / Allow `Enter` with the keys inside the buttons, red for a destructive call); the transcript keeps the diff band (Home: `ApprovalRequest`, the same band) without buttons, hides the running call the request is holding (the engine reports both, so the edit showed twice), and the live line hides too. In either composer Escape denies a pending call (in Code it used to stop the whole run) and Enter on an empty field allows it; edited files are listed by the turn's `FileChangesCard`, not again as chips under the work block. The TUI approval card speaks the same grammar (`widgets/approval.rs`): docked above the composer instead of floating over the transcript, the question by kind ("Allow this edit?", "Run this command?"), one tint `●` (amber, red when destructive), the diff (its header names the file and counts) or the wrapped command, and Allow `Enter` / Allow for turn `A` / Deny `Esc` with `Y`/`N` still accepted. Settled step verbs are `--text-secondary` and the running one is the only bright row, with the live line's shimmer; the work-block header is the rows' size, dimmer. `activitySummary` skips approval steps, which counted an edit waiting on you as a second file
- **Reading text** (`.markdown-body` in `app.css`): body text takes `--prose-ink`, a step under the foreground in dark mode (full white glares over a long answer) and the foreground again under raised contrast; headings, bold, `th` and `dt` stay at full strength so the eye has landmarks. Line height 1.65, list items 0.4em apart, headings 1.75em above and 0.5em below so each binds to its section, measure 56ch (~72 characters). Citations are `.md-cite`: a small raised number on a soft fill, with no space before it, kept on one line with its word and any punctuation that follows it (`.md-cite-group`)
- **Subagent cards** (`SubagentCard.svelte` inside a `Disclosure`): a child is an agent, not a call, so it is drawn as an object — identity (kind, description, cost) over the live line (meter, activity, elapsed) over the footer (tools · model · cache), with Stop on the first row so a runaway child dies without being opened. A linked child draws on its `task` step's row, where the work block counts it as a step; spawns no step claims each get their own card in `CodeTranscript`
- **Project picker** (desktop Code, `ProjectSelector.svelte` on the composer bar, before the mode): a conversation's folder is chosen where you write, not before. The rail's New conversation (and Ctrl/⌘+K) calls `codeStore.startConversation()` — the project you were last in, else the first, else Add project first — and the chip lists every added project (name hard left, path dim on the right, the one in effect checked) plus "Add project…", which adds one and points the conversation at it. `setConversationProject` works only while `canChangeProject` (no message, no engine session); after that the chip is a plain label whose tooltip says to start a new conversation for another folder. Add project itself moved to the folder-plus in the Projects header; the old folder line above an empty conversation is gone (the chip says it)
- **Add project** (desktop Code, `FolderBrowserDialog.svelte`): one dialog, three tabs with no track box — Open folder (the in-app `FolderBrowser`; the pencil, Ctrl+L, `/` or `~` turns the crumbs into a path field, `~` expands in main), New folder (a name, `git init` on by default) and Clone (an https/ssh/`git@host:owner/repo` URL, folder name from the repo). New and Clone share an "In ~/Code · Change" line — the projects folder, remembered per viewer (`agente.code.projectsRoot`; else Code/Projects/repos… in home, else home) — and the footer says what will happen ("Creates ~/Code/my-app") on its left edge with the one action on its right; a problem takes that place in red. Every tab is the folder browser's height, so switching never moves the dialog. Main does the work (`main/project-setup.ts`, channels `create_project_folder` / `clone_project_repo`): the rules are shared (`shared/project-setup.ts`, problem codes the dialog translates), the target must not exist, clones run `git -c protocol.ext.allow=never -c protocol.file.allow=never clone -- <url> <dir>` with `GIT_TERMINAL_PROMPT=0` and a 15-minute limit, and a failed clone removes the half-written folder; a failed `git init` still keeps the new folder
- **Pane strip chips** (`PanelTabs.svelte`): Changes, Files and Plan carry their names while Terminal, Processes, Canvas, Browser and History stay icons, and `@container (max-width: 46rem)` folds the names back into the icons they always had — the `container-type` the strip declared from the start and never used. The diff badge groups its digits; note that it counts a created file's whole length as additions (`crates/agente-daemon/src/git.rs` reads the file), so one generated file can still dwarf a hand-written change
- **Tool execution modes**: read/grep/list run in parallel; write/edit/shell run sequential; one `Sequential` tool forces the whole batch sequential
- **Cancel channel**: abort signals let Escape interrupt actually abort the LLM task; the stop button works even while a modal owns the screen
- **Tool result truncation**: shell=500 lines, read=2000 lines, grep=200 chars/line, list=500 entries
- **Web reading** (no character budgets): pages come back whole as markdown — main content only, with headings, lists, tables, code and links, and no menus, banners, scripts or hidden text. Core `web_fetch` (`tools/web/`: `extract.rs` on `scraper`/html5ever) decodes the page's charset, returns the whole page with metadata and links, and splits it into `offset` parts only when the model passes `max_chars`; Desktop delegates HTML scraping to Rust `web.fetch` and keeps `main/web-scraper.ts` for SSRF URL checks and binary PDF/DOCX extraction. Core `web_search` uses `<config dir>/web.json` (DuckDuckGo default; Brave/Tavily/Exa keys from `auth.json` `web:<id>` or their env vars; SearXNG URL), falls back to DuckDuckGo and says so; `/settings` → Web search cycles it. Desktop's Settings → Search drive it too: `main/agente/core-web.ts` sends the choice, SearXNG URL and Brave/Tavily/Exa keys to the daemon's `web.sync` when a runtime connection opens and on every search-settings save (Desktop is the source of truth; desktop-only providers such as the aggregator map to the first keyed provider, else DuckDuckGo)
- **Edit contract** (`crates/agente-core/src/tools/edit_match.rs`): every edit goes through one graded matcher — exact → trailing whitespace → whitespace/indentation → Unicode/CRLF normalization → blank-line tolerant → line-level similarity ≥ 90 % — and the first level with **exactly one** match wins. Ambiguity is a refusal that lists the candidates and hands back the exact `old` to retry with; nothing is applied on a guess. `edits[]` and the legacy `search`/`replace` share that ladder, so the same intent cannot succeed in one spelling and fail in the other. An already-applied edit (old gone, new present once) is a success that writes nothing; `nearLine` only breaks ties; the result names the tolerance used (`edited path:12-14 (whitespace) · 3 → 5 lines`). A ranged read records the whole-file hash (so read-a-range-then-edit works) but still refuses a whole-file `write_file`; a failed call no longer aborts its batch siblings — only a second edit to a file this batch already changed is skipped, with the reason. `apply_patch` reports every hunk (`#2 applied at line 30 (+3 lines)`), tolerates whitespace drift in context lines, and a failed hunk names the context it wanted and what the file has. Post-write diagnostics come only from real parsers (today the JSON check, `lsp::quick_validate_syntax`): the hand-rolled Rust brace counter is gone because it flagged files that compiled
- **Compaction**: at 85% of the room (not the raw window) the loop emits `CompactionStarted`, then trims (truncate old tool results, compress prose, drop old turns) — or, with the `smart_compaction` setting (off by default, `/settings`), writes an LLM checkpoint and falls back to trimming on failure. A pass that saves nothing is not announced: it retries once with `compact_forced` and otherwise leaves the transcript alone. `ContextCompacted` carries before/after tokens: the transcript gets a `⟲ Context compacted · 182k → 64k · summarized|trimmed` divider. Provider-reported overflow forces a trim + retry (max 2 per turn); manual `/compact` always trims; subagents always trim
- **Context budget** (`crates/agente-core/src/context/budget.rs`): `ContextBudget` is the one arithmetic — window minus tool schemas, minus the tokenizer gap the provider reported last time, minus the reply reserve, floored at a quarter of the window. The compaction gate, the compactor's strategy (`CompactionStrategy::from_budget`), the TUI meter (`AgentEvent::ContextBudget` → `state.agent.context`) and the desktop ring all read it, so the amber line and the compaction line are the same place; `estimate_message_tokens` is the only estimator and counts reasoning and continuations, not just text. `tokenizer_gap` outlives the turn (`initial_gap` in, the event's `gap` back out), so a turn's first request is not gated blind. llama-server's `n_ctx` from `/props` becomes the window unless one was configured. The model is told: `ContextBudget::notice_message` appends one banded reminder (half / quarter / tenth of the room, plus one right after a compaction) to the request copy only — never to the transcript, so session files, forks, resumed children and the chat stay clean, and appending last keeps the cached prefix byte-stable. No reminder while more than half the room is free
- **Provider specs** (`crates/agente-core/providers/*.toml`, `providers/spec.rs`): one TOML per provider — endpoint, `api_format`, key vars, `match_hosts`, `models` source (`catalog` | `openrouter` | `openai_models` | `llamacpp`), `thinking` request shape, `offered` (replaces the old allowlist), `key_url` / `docs_url`, `order`, `openai_compatible_url` (for clients that only speak OpenAI chat, e.g. MiniMax's `/v1` beside its Anthropic API), plus fallback model data (`models_seed.<id>` `output`/`input`/`reasoning`, provider-wide `default_reasoning`, models.dev `reasoning_options` shape) used only where the provider and models.dev say nothing. Adding a provider = a file + a line in `SOURCES`; the TUI and Desktop pick it up — Desktop has no provider list of its own (`renderer/src/lib/utils/provider-directory.svelte.ts` loads `providers.list`; `llamacpp` keeps its own "On this computer" section). Services whose terms forbid using a person's key from third-party apps stay out (see `apps/desktop/shared/providers.ts`)
- **Thinking profile** (`thinking.rs`): `profile(model)` → levels low → high with token budgets, the provider default `auto` resolves to, and `mandatory`; `request_patch` builds the wire fields from the same profile, so no UI offers a level the wire drops. `auto` (send nothing) is the default level. Sources: models.dev, OpenRouter's live `reasoning` object (descending `supported_efforts` re-sorted), llama-server `/props` (`providers/llamacpp.rs`: template detector ported from llama.cpp's WebUI, `chat_template_caps` → per-request `enable_thinking` + `thinking_budget_tokens` ladder 512/2k/8k/∞). Live model discovery lives in `agente_core::models` (TUI and runtime share it); the models.dev cache refreshes in the background after 24 h. Desktop asks the daemon (`models.discover`, `models.thinking`, `thinking.request`, `thinking.template`) through `apps/desktop/main/agente/thinking.ts` — it has no level lists or body builders of its own
- **System message concatenation**: mode restrictions are appended to the system prompt, never a separate message
- **Transport policy** (`providers/policy.rs`, `docs/PROVIDERS.md`): shared route precedence is explicit model configuration → explicit live metadata → explicit catalog metadata → documented `transport.model_routes` → provider protocol default, only when `require_model_route` is unset/false. Go discovery determines membership; missing routes stay listed and fail before completion HTTP with a `models.<id>.provider.api_format` configuration hint. `models.info`/discovery expose additive transport readiness. Desktop aliases normalize policy and retain the core result when using the same endpoint. Catalog refresh and registry rebuilds preserve overrides
- **Prompt caching**: the request prefix must be byte-stable — tool definitions are sorted by name (the registry is a `HashMap` rebuilt per turn); `providers/cache.rs` consumes declarative `transport.cache` defaults/rules and model `cache_control: true|false` overrides. It annotates system + two newest user turns on a separate copy of the complete request. Only HTTP 400/422 explicitly rejecting the unsupported parameter retries once, and only when Agente inserted markers; the retained original preserves user fields and content shapes. Cache hits in every usage dialect (`prompt_tokens_details.cached_tokens`, DeepSeek `prompt_cache_hit_tokens`, `cache_write_tokens`) share usage accounting
- **Spend**: every model call emits `AgentEvent::CallUsage` with its cost, priced by one rule (`ModelCost::call_cost`): the provider's own charge when it reports one (OpenRouter `usage.cost`, always in the final chunk; `cost_details.upstream_inference_cost` is added only when the provider spec sets `transport.billing.byok`, since without BYOK `cost` already includes it), else the catalog/live `/models` per-million price — tagged with the `subagent_id` that made it. A model added by id has no configured price, so `apply_catalog_cost` fills `ModelCost` from models.dev when the resolution would otherwise be unpriced; an explicit configured price still wins. Summed into `agent.spend` (status row `$0.042 · 82% cached`) and per child (`SubagentUiState::spend`, on the card and detail title); unpriced models show only the cache rate. One money formatter per surface and the same rule on both (`<$0.001` below a tenth of a cent, three decimals below $1, two above): the TUI's `state::format_usd` and the desktop's `utils/money.ts`; honest labels `~` = catalog estimate, `+` = some calls unpriced, `free` = provider charged $0, cache % floored and hidden until the provider reports cache fields. Prices: OpenRouter `usage.cost` → OpenRouter `/models` per-token pricing → models.dev per-1M `cost` including context `tiers` (the whole call bills at the tier once the prompt passes its size). OpenCode Go reports no per-call cost; its models.dev prices are what its dollar allowance ($12/5h, $30/week, $60/month) is charged at, so Go spend is shown as an estimate
- **Provider cache notes**: DeepSeek/GLM cache automatically on an exact prefix (hits in `prompt_cache_hit_tokens` / `prompt_tokens_details.cached_tokens`); MiniMax's Anthropic API caches only `cache_control` breakpoints (≤4); Go's TOML enables a session `prompt_cache_key` on every route, with protocol defaults enabling markers only for Messages. OpenRouter's Claude/Gemini marker rules also live in TOML. These defaults are configurable; transport builders contain no provider/model cache branches. Gateways may report several dialects at once, so the largest cache count wins
- **Categorized errors**: API errors show actionable messages with `/compact`, `/model`, `/provider` hints
- **Subagents**: `task` / `task_output` / `kill_task` hosted tools routed to `SubagentHost`. There are no predetermined subagents: the parent model creates each one for its task — `role` (shown on the card; defaults to the description), optional `instructions`, `capability_mode` (read-only by default) and a `model` — on the base prompt `crates/agente-core/agents/_role.md`; the user's own `.agente/agents/*.md` still launch by name (`subagent_type`, listed only when they exist). Models come from the user's list (`config::SubagentSettings`: entries with a name, provider/model, thinking and a `use_for` note the parent reads; one `default_model`; `orchestrator_picks`), routed by `subagent::routing::resolve_model` — the parent's pick (list name or `main`; anything else fails the call) → an agent file's `model:` → the default → the parent's model; old per-type `subagent_models` pins fold into the list on read. The list's menu (price, window, note) is appended to the `task` description byte-stably; cards show `name · model` (`ChildStarted.seat`). Edited in the TUI `/subagent-models` and Desktop's Subagents dialog (`SubagentModelsEditor.svelte`), both laid out by the Laws of UX: one radio per row for the default with the conversation's model as the last option, names folded into shape instead of refused, a row without a model kept as a draft. A read-only child waits inline, one that may change things runs in the background; children run unbounded (the wall-clock watchdog is the backstop); writing children get an isolated git worktree (two kept warm), read-only children read the parent root directly — no checkout; up to `max_parallel_subagents` (default 8, `/settings`) run at once, the rest queue FIFO; parent + child approvals route by `request_id` via `ApprovalBroker`. Roadmap (limits/recovery, durable children, swarm): `docs/SUBAGENTS_PLAN.md`
- **Swarm mode** (`crates/agente-core/src/swarm.rs`, `subagent/host/board.rs`): a per-session switch (`BoardStore`, `~/.agente/sessions/boards/<session>.json`, daemon `board.get|enable|clear`) that gives the main model the hosted `board` tool. It adds cards — title, role, `capability_mode` (read-only default), model, prompt, `depends_on`, `owns` — and the host starts every card whose dependencies are done as a created background subagent (the card's prompt plus its files and the results it builds on); readers land in Done, writers in Review, failures in Failed; `move` accepts, sends back with a note (a fresh subagent retries) or gives up. One writer per path: a writer's `owns` may not overlap another open writer's. Members talk through the board's findings log (`Board.findings`): each card's child gets the `swarm` tool (`post` a finding, optionally `to` some cards; `read` the cards and log) and an inbox, so a post reaches the members still working at their next step (no reply expected) and every card that starts later in its prompt; the lead sees the newest ten in every `board` result and broadcasts with `board` `post`. One view: a turn's swarm members draw as one block — Desktop `SwarmBlock.svelte` (a lane per card: status, id, title, role · model, activity hard right, waits for / feeds, then the newest findings via the shared `SwarmFindingList`) instead of the subagent tally line, the Board pane lists the whole log under its columns; TUI member cards read `c2 Title  Role` with `· feeds c3` and `✎ c1 → c2  finding`, and `/board` shows the newest findings under the columns. `AgentEvent::BoardChanged` → `RuntimeEvent::BoardChanged` carries the whole board. TUI: `/swarm` toggles, `/board` shows the columns, the status row says `+ swarm`. Desktop: the switch sits in the composer's mode menu (the trigger reads `Auto + Swarm`), and a Board pane (`BoardPanel.svelte`, `swarm.svelte.ts`) shows Backlog / Working / Review / Done — side by side when wide, stacked in a side pane — cards are borderless rows lit on hover (no rails), review marked only by its amber `◆`; its chip appears only while swarm is on or cards remain
- **Loop guard**: identical tool-call signatures nudge after 3 repeats, hard-stop after 6 with a visible notice
- **Skills** (Agent Skills spec, `extensions/skills.rs`): folders with a `SKILL.md` discovered in `~/.claude|.agents|.config/agente|.agente/skills` then `<project>/.claude|.agents|.agente/skills` (later wins, so project beats user); lenient frontmatter (block scalars, nested `metadata`, colons in values), only a missing description skips a skill. Progressive disclosure: the catalog (name + description) lives in the `skill` tool's description with a `name` enum — the model picks the skill itself, and the tool is not registered when there are none; activation returns `<skill_content name="…">` with the body, skill dir and a resource listing (files are read on demand — `read_file`/`list_dir`/`grep`/`find` may open files inside skill dirs outside the project via `resolve_read_path`). `/skill-name request` injects the same block from the composer (the bubble shows what was typed); `/skills` lists them; `disable-model-invocation` keeps one manual-only. Compaction never truncates a skill block and re-attaches any it dropped (`carry_skills`)
- **Desktop typography** (`apps/desktop/renderer/src/app.css`, `lib/stores/accessibility.svelte.ts`): one type ladder (`--text-prose|base|sm|xs|code`) multiplied by `--reading-scale`, so Settings → Text size moves captions, chrome, prose, code, diffs and the terminal together; interface size is a window zoom on top of it and reaches 200% (WCAG 1.4.4 wants no less). Nothing hardcodes below `--text-xs` (12px at 100%, the smallest legible regular size); the one exception is the scaled-down page preview in `ArtifactThumb`, which is artwork. Monaco and xterm resolve the tokens through `utils/type-tokens.ts` because canvas cannot read `var()`. Fonts are OFL only and bundled: Inter Variable, IBM Plex Mono, and the Atkinson Hyperlegible pair, where the reading font also swaps `--font-mono` so code follows it. The OS preference reaches the app too: `prefers-contrast: more` raises the same tokens as the manual switch, `forced-colors: active` drops decoration. Zoom belongs to the setting, not to Chromium (`setZoomMode('manual')` plus `zoom-changed` feeding the same presets)
- **MCP** (`mcp/`, official `rmcp` SDK): stdio child processes (stderr captured, never inherited) and Streamable HTTP (session id, protocol header, bearer/custom headers). `Arc<McpManager>` with per-server state and no lock across I/O — servers connect concurrently in the background, turns register whichever are ready, calls run concurrently; `tools/list_changed` re-lists on the next turn. Config: `agente.json` `mcp` (lenient: `_comment` keys skipped, `command` string + `args` accepted) plus the project's `.mcp.json` (`mcpServers`), which waits for approval in `/mcp` (`approved_mcp_servers`). Permissions come from `Tool::default_permission`: `readOnlyHint` tools run unasked and in Plan mode, others Ask (auto-approve still applies) unless `trust: true`; `isError` results fail the call. A new session in the same project keeps live connections

- **Browser extension + bridge** (`crates/agente-bridge`, `apps/desktop/extension`, `npm run build:extension` → `dist-extension/{chrome,firefox}`): one MV3 source for Chrome and Firefox. `agente bridge` is a stdio MCP server (`agente bridge install` registers it as `web` in `~/.agente/config.json`), so every surface gets `web_browser_*` (the panel driver's actions, snapshot script and text, shared via `apps/desktop/shared/browser/`), `web_tab_context`, `web_page_extract`, `web_doc_*`, `web_sheet_*`, `web_drive_*`; read-only annotations decide what runs unasked. The first bridge to bind `127.0.0.1:7391` is the hub the extension pairs with (`port.token` code from `agente bridge status`); later sessions forward through it as peers. Google: the user's own OAuth client (`agente bridge auth google`, `docs/GOOGLE_WORKSPACE.md`); with no sign-in, doc/sheet *reads* go through the user's browser session (export / gviz endpoints, docs.google.com only). The side panel is a small chat answered by Desktop: Desktop joins the hub as `app` (`main/agente/browser-chat.ts`, starting `agente bridge serve` when nobody listens), the renderer runs each message as a Home turn (`services/browser-chat.ts`), and those chats carry `origin: 'browser'` (chats column) and sit in the Home sidebar's Browser group. Chat bodies are `shared/browser/chat-protocol.ts`; the hub relays them unread

- **Design space** (`apps/desktop`: `main/design/`, `renderer/src/lib/features/design/`, `shared/design.ts`): a fourth space (`SpaceId`/`ChatContextMode` `design`, `PenTool` in the rail, `context_mode='design'` — no migration, the column is TEXT). Each chat owns `<app data>/designs/<chatId>/` with plain HTML + `tokens.css` + `DESIGN.md` + `assets/`, no build step; `.versions/` holds snapshots (a version at every turn end, restore saves the current state first) and `variants/<name>/index.html` holds alternatives that link `../../tokens.css` (promote copies them up and rewrites the prefix). The turn is Home's (`runHomeRuntime` with a `SpaceRuntime` in `services/agent-design-runtime.ts`: design prompt + tools instead of research bootstrap and reply review, 60 iterations / 160 calls / 20 min; a turn that runs out of iterations gets one tool-less wrap-up attempt (`ITERATION_LIMIT_NOTICE` in `agent-home-runtime.ts`) so it ends with a summary instead of the core's pause notice). Tools — `design_list|read|write|edit|snapshot|preview|inspect` plus Home's read-only `web_search`/`fetch_url`, no shell, git, delete or image generation — are enforced in main: `workspace.ts` `resolveInside` rejects NUL, absolute/drive/`~` paths, `..`, `.versions` and any symlink in the chain (specs prove each); the renderer is never trusted. `design_preview`/`design_inspect` inline the page with `buildPreviewHtml` (the canvas's own builder) and main renders it in the offline artifact guest (`design/render.ts`): a PNG when `agente_model_inputs` lists `image`, otherwise a compact outline (boxes, text, key styles, overflow flags), always with console errors and blocked external refs. The canvas (`DesignCanvas`) is a board you pan and zoom: a row per page then per variant, one labelled frame per size switched on in the top bar (390 / 834 / 1440, any mix; `boardLayout` in `design-view.ts`), each a sandboxed `srcdoc` frame (`allow-scripts`, opaque origin) at that device's screen size; zoom null = fitted, otherwise an explicit scale + pan (`zoomAt` keeps the point under the pointer); frames far off screen draw a blank sheet. Labels, pins, the selection prompt and the comment draft live in a screen layer so they keep their size; picks and comments carry the frame's page and width ("in the 390px frame" in the turn context). Drag a label to move a frame (positions saved per design in localStorage; More → Tidy up board resets), double-click it to zoom to the frame, right-click or ⋯ for its menu: zoom, ask for a variant (fills the composer), use a variant, delete a page/variant (`design_manage` `remove`: never the entry page, a version is saved first). `design_changed` from main reloads it; the variants/versions tray sits under it; chat docks right and hides without unmounting. Keys are Ctrl/⌘+Alt+ `1–3` toggle a size on the board, `4` fit, `R` reload, `V` variants, `T` versions, `C` chat, `I` inspector. Pointing (`design-picker.ts`): the canvas injects an ES5 picker into the frame (never into the agent's renders) and talks only by `postMessage`, checked against the frame's window and shape (`readFrameMessage`); the `DesignToolPill` dock at the bottom of the canvas switches Browse / Select / Comment (`V`/`S`/`C` outside editables) and carries the zoom; the top bar keeps only the page, the viewport switch, variants/versions/inspector, More and Export. Each pointing tool has its own pointer (`design-cursors.ts`: ink arrow + ember badge, sent to the frame with the `tool` message), and picks are outlined in ember. In Select a prompt opens under the last pick (`DesignSelectionPrompt`): Enter sends through the composer's own send path, so the selection rides the turn as usual. Select outlines and reports selector, text, trimmed outerHTML and key styles (shift adds); Comment pins numbered notes; double-click edits leaf text in place — written with `design_edit` when the old text occurs exactly once, else queued as a comment. Selections and comments show as chips above the composer and ride the next turn only, through `designStore.takeTurnContext()` into that turn's system prompt. `DesignInspector` (Element / Tokens / Code): token edits rewrite one declaration of `tokens.css` (`design-tokens.ts`). Zoom presets + Ctrl+wheel, a light/dark/auto preview scheme (the iframe's `color-scheme`), and Export (copy HTML, save via dialog, open in browser from `<app data>/design-exports/`). Design systems (`main/design/systems.ts`, channel `design_systems`): a library in `<app data>/design-systems/<id>/` (`system.json`, `tokens.css`, `DESIGN.md`, optional `components.html` specimen, `assets/`), slug ids validated before any path; save from a design, import from a folder (reads tokens/CSS custom properties/tailwind theme text only, never runs anything), apply (snapshots first); the link lives beside the workspace in `designs/<chatId>.system.json` so the agent's listing never shows it, and the briefing carries the system's DESIGN.md + tokens. Handoff (`main/design/handoff.ts`, channel `design_handoff`, `design-handoff.ts`): a deterministic `HANDOFF.md` (pages, light/dark token table, shared classes, states, breakpoints, assets, static a11y checks); a zip bundle (workspace without `.versions`, HANDOFF.md, one inlined HTML per page); "Hand off to Code" copies into `<project>/.agente/designs/<slug>/` only after the dialog's confirm (never overwrites: `-2`, `-3`), opens a Code conversation there and fills — never sends — the build prompt. The Canvas pane stays the image annotator. **Phase 3**: *Edit toolbar* (`DesignEditBar`, `design-edit-ops.ts`, `design-source.ts`): with one element selected a toolbar floats above it (text size −/+, bold, text/background colour from tokens.css `var(--x)` swatches or a neutral+ember set, radius and padding steps, ⋯ copy selector / show in Code); each click is a direct edit of the element's inline `style` — `design-source.ts` scans the page source without a DOM (offsets, optional end tags, picker selector grammar), `planStyleEdit` returns an exact-once `design_edit` (old_text widened by whole lines until unique) or, when the element is not found exactly once, a comment for the agent; edits run through one queue in `designStore.applyStyleEdit`, with an auto snapshot before the first edit of a 20 s burst (Versions is the undo), the frame keeps its scroll and re-picks the element after the reload. *Layers* (`DesignLayers`, `design-layers.ts`, Ctrl/⌘+Alt+L): a floating tree built from the page source, hover outlines the element in the frame, click/Enter sends a `pick` message to the picker (Select tool takes over), arrows/Left/Right/Home/End. *Draw* (`D`, `design-strokes.ts`): ember 2 px freehand marks on a screen-layer SVG, stored in page coordinates per frame; the frame answers a `probe` message with the selectors under sampled points and `formatTurnContext` adds a "Marks drawn on the canvas" block (box + elements crossed); Backspace/Esc remove the last mark; marks clear after the turn. *Tweaks* (`DesignTweaks`, `design-tweaks.ts`): the agent declares `tweaks.json` (range/color/choice bound to a `:root` custom property in tokens.css, taught in `services/design-prompts.ts`); they show at the top of the inspector's Tokens tab (next to the tokens they edit, and the inspector is where the file's values already live, so no second surface under the chat), move live via a `cssvar` message to every frame and settle into one `tokens.css` declaration through `designStore.writeToken`. References and flows (phase 4): the dock's image entry adds pictures to `references/` (main's file dialog `pick_references`, drop on the canvas, paste outside a field) or captures a public website (`design_reference` with `saveScreenshot`: main's private public-http(s)-only window, never the renderer); thumbnails with × sit above the composer (`DesignReferences`), `remove_reference` only deletes direct children of `references/`, and the turn's briefing adds a "Match the references" block. Flows: `flows.json` (`shared/design-flows.ts`, written only by `set_flows` after main checks every link against existing pages, or by the agent, read leniently) draws quiet arrows between same-size frames on the board; the frame menu has Link to… (toggle), Generate next screen (fills the composer, never sends) and exports. `export_png` (full-length, at the frame's width) and `export_pdf` (one tall page) render in the offline guest (`render.ts` `renderPdf`, `export.ts` helpers) and save through a save dialog; `editBarPlacement` takes the frame's top as a ceiling so the edit bar never covers a frame label

- **Opt-in spaces** (`apps/desktop`): Home, Code and Design are always available. Roleplay is opt-in through Settings; disabling it returns the window to Home.

- **Roleplay** (`apps/desktop`: `renderer/src/lib/features/roleplay/`, `services/roleplay-*.ts`): **Macros** (`roleplay-macros.ts` `resolveMacros`): stored text is always raw (messages, greetings, cards, journal, props); it resolves at display and on the wire per message — `{{char}}` is that message's speaker, `{{user}}` the active persona, time macros use the message's `createdAt`, random/pick/roll seed by message id — so a persona switch re-resolves old messages. Editors show raw text; `MacroField` offers "Insert name" with a live preview. **Prompt** (`roleplay-prompts.ts` `buildRoleplayPromptParts`): a byte-stable block first (instructions, content frame, world, every cast card in roster order, the scene primary's scenario/examples/post-history — never the per-turn speaker — persona, mode policy), then history, then one volatile tail (lore by id, NPCs, memory, room, notes for the AI, group turn, choices, props, steering, speaker nudge); anything reading `{{lastMessage}}` moves to the tail. This keeps llama-server's prefix cache and implicit provider caching warm. **Budget** (`roleplay-budget.ts`): window from the local `n_ctx` or the catalog; reserve min(max_tokens, 25%); trims examples → lore → long descriptions → oldest history, never the greeting or the new turn, and records `recall.trimmed`. Failed replies never go back as history. **Local**: a sampler preset sent only to the local dialect (`extra_params`: min_p, DRY or repeat_penalty, max_tokens 400), thinking off by default, summaries only when the context is near full. **UX**: one click on a character starts a 1:1 scene (Customize scene for world/cast/opening/persona); plain names — Openings, How they talk (sample exchanges ↔ `<START>`), Lore/Triggers, Notes for the AI, Advanced; Pin to memory + `SceneMemory`; `RecallLine` shows what each reply used. Harness: `tests/electron/roleplay.smoke.ts`. Not done: cache_control markers for Anthropic-style cloud roleplay, `id_slot` pinning (needs `--parallel` > 1).

## Layout

- `crates/agente-core` — agent loop, tools, providers, permissions, subagents, context/compaction
- `crates/agente-tui` — terminal UI (`app/` run loop, `state/`, `widgets/`, dialogs, `ui_harness.rs`)
- `crates/agente-cli` — `agente` binary (TUI + headless)
- `crates/agente-{acp,daemon,runtime,session,protocol}` — embedding, persistence, local-socket/TCP daemon for Desktop & `agente attach`
- `crates/agente-bridge` — `agente bridge`: browser-extension hub + `web` MCP tools + Google Docs/Sheets/Drive; `apps/desktop/extension` — the Chrome/Firefox extension
- `<project>/agente.json` — project config (`agente.json.example` is the template); `<project>/.agente/` — sessions, worktrees, commands, agents, skills

## Visual harness (`crates/agente-tui/src/ui_harness.rs`)

Test-only module rendering the composed frame for a catalogue of realistic app states. Rules worth keeping: clamp every dialog row with `widgets::centered_panel` / `panel_row` (a size preference is not a promise); `panel_bg` = `Clear` plus a background `Block`; chrome glyphs must be single-width; floating dialogs render into the content rect, never the whole frame.

## Known gaps

- Two turn engines remain: the TUI runs `agente_core::agent::channel`, `--no-tui` / `--acp-stdio` run `RuntimeSupervisor`. Converging them is a separate piece of work.
- Connect *dialog* end-to-end with a real key entered through the UI (the headless provider path is verified)
- Approval flow hooks for security plugins
- fsnotify-based file-change detection + write-conflict guard
- MCP OAuth flows (bearer tokens via `headers` work), MCP resources/prompts, and deferred tool search for large MCP tool sets
- Project skills load with AGENTS.md's trust (no per-repo trust prompt yet); project `.mcp.json` servers already wait for approval
- Converging `agente-tui` onto `agente-runtime`/`agente-session` (one turn engine and session store across TUI, Desktop, CLI, and ACP)
- Desktop attention notifications; audio/video playback previews in the TUI
- `CodeStepRow` still spins a `Loader2` while a step runs: every other working surface now speaks the tile meter, but that icon doubles as the done/error/approval mark, so replacing only its running state is its own change
- `tests/electron/subagent-rendering.smoke.ts` fails on its compaction assertion (`Compaction token counts missing`) on unmodified code — the report no longer prints the formatted `12,000` the test looks for. The card assertions in the same file pass and are worth keeping green

- Bridge: when the hub process exits (its session closed), peer sessions keep retrying a dead port instead of taking it over; Desktop restarts a hub, a TUI-only setup does not. Writes into Office on the web and paste-based writes into open Google docs are not built (writes need the Google API). The MV3 worker's keep-alive (pings + 30 s alarm) is untested over long idle periods
